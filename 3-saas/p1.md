# PRD 3 — SaaS
## Phase 1: Multi-Tenancy Foundation

### Goal
Mengubah CMS single-school menjadi platform yang dapat digunakan banyak sekolah secara terisolasi.

### Core Concept
Setiap sekolah = tenant.

### Core Entities
- schools
- users
- memberships
- school_settings

### Tenant Rules
- Semua data konten harus memiliki school_id
- User hanya dapat mengakses school yang menjadi membership-nya
- Query wajib scoped berdasarkan tenant
- Tidak boleh ada data leakage antar sekolah

### Scope
- Tenant resolution
- school_id pada semua tabel relevan
- Migration data existing
- Tenant-aware queries
- School switcher jika user punya lebih dari satu school
- School settings dasar

### Domain Strategy
Phase awal:
- subdomain opsional
- custom domain belum wajib

### Acceptance Criteria
- Dua sekolah dapat memiliki data berbeda
- Admin sekolah A tidak dapat membaca/mengubah data sekolah B
- Public website resolve sekolah yang benar
