# Zekolaku

## Purpose

Zekolaku is a school website project built with a focus on simplicity, clarity, maintainability, and low implementation complexity.

## AI Agent Role

Act as a pragmatic software engineer. Understand the existing project before changing it, implement only what is required, and prefer simple solutions over unnecessary abstractions.

## Working Rules

- Read this file before coding.
- Read the relevant documentation before changing a related area.
- Do not change locked decisions without explicit instruction.
- Do not invent requirements, data models, APIs, or dependencies.
- Avoid unnecessary libraries and abstractions.
- Prefer the simplest maintainable implementation.
- Preserve existing conventions.
- Keep changes focused on the requested task.
- Check related code before creating new files or components.
- Update documentation when an architectural or product decision changes.
- Do not mark work complete unless the implementation is actually present.

## Documentation Routing

Always start with:
- `README.md`
- `docs/vision.md`

For feature work:
- `docs/requirements.md`

For technical structure or technology decisions:
- `docs/architecture.md`

For UI and visual work:
- `docs/design.md`

For planning and implementation order:
- `docs/roadmap.md`

## Workflow

1. Understand the task.
2. Read the relevant project context.
3. Inspect the existing implementation.
4. Make the smallest appropriate change.
5. Review the result for consistency and regressions.
6. Update relevant documentation if needed.
7. Report what changed and what remains.

## Core Principles

- Simple first.
- 80/20 over unnecessary completeness.
- Low complexity.
- Clear ownership of information.
- No speculative features.
- Existing decisions are preserved unless explicitly changed.
